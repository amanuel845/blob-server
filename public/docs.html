TikTok JSON Uploader
App Help

📖 Documentation

Overview

The TikTok JSON Uploader is a client‑side tool for uploading, managing, and viewing files stored in a Vercel Blob storage backend. It is designed for TikTok data analysts and content creators who need to store and retrieve JSON files (or any other file type) with ease.

Architecture

The app consists of several modules:

  • config.js – central configuration with getters/setters and localStorage persistence.
  • dom.js – caches all DOM references for performance.
  • encryptor.js – AES‑GCM encryption/decryption for API keys.
  • auth.js – handles authentication, key fetching, and storage.
  • helper.js – formatting, filename manipulation, icon mapping.
  • uploader.js – core upload (single, chunked, direct), delete, list, read.
  • main.js – UI controller, event binding, pagination, modals.

Upload Flow

  1. User selects one or more files (drag‑and‑drop or file picker).
  2. For each file, the app determines the upload method:
    • Small files (≤ threshold, default 4 MB) are sent via a standard POST to the server.
    • Large files are uploaded via a presigned URL (direct browser‑to‑storage).
  3. Progress is shown per file and overall.
  4. After completion, the file list is refreshed.
Note: The presigned‑URL method bypasses the server’s 4.5 MB request limit, allowing files up to 5 TB.

File Management

Listing

The Files tab displays all blobs in a sortable table. You can sort by name or size. Pagination is available for large collections.

Viewing

Click the View button (👁️) on any file to load its content into the code viewer (only JSON files can be displayed). The viewer runs in a Web Worker, so the UI remains responsive.

Download

Click the Download button (⬇️) to open the file in a new tab (or trigger a download if the browser supports it).

Delete

You can delete a single file using the trash icon, or select multiple files and use the Delete Selected button. A confirmation modal prevents accidental deletions.

Configuration

The Config tab lets you adjust global settings:

  • apiBase – backend endpoint URL.
  • blobdbEndpoint – API path (e.g., /server).
  • encryptedKeyEndpoint – path to fetch the encrypted key.
  • storageKey – key used for localStorage.
  • defaultCategory – default folder for uploads.
  • uploadThreshold – size in bytes above which direct upload is used.
  • smoothingFactor – speed calculation smoothing.
  • filterEnabled – show only files in the current category.

Changes are saved automatically to localStorage and applied immediately.

Security

  • The API key is never sent in plaintext – it is encrypted with a user‑provided password using AES‑GCM.
  • The encrypted key is fetched from the server once; decryption happens only in the browser.
  • All requests include an Authorization header with the decrypted key.
  • Presigned URLs are short‑lived (15 minutes) and scoped to a specific path.

Performance Tips

  • For very large JSON files, use the direct upload (it will auto‑select if > threshold).
  • Use the Refresh button sparingly – the app caches the blob list and updates it locally after deletions/uploads.
  • If you have hundreds of files, adjust the page size in the Files tab to 50 or 100.

Limitations

  • The code viewer only works for JSON files; other file types show a blank preview.
  • Deleting a large number of files (>100) may take a while – the spinner shows progress.
  • The app relies on the server’s CORS configuration – ensure your backend allows requests from your domain.
